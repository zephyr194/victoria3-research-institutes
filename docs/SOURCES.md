## Building schema discrepancy

The [shared building schema](https://github.com/Victoria-3-Modding-Co-op/Modding-Digests/blob/76ba7b4bfc217a61ff19bbe869027b78d5743055/documentation/types/buildings.md) lists `production_methods` and `construction_points`. The game's script-facing fields are instead recorded as `production_method_groups` and `required_construction` by the [pdx-parser-go implementation](https://github.com/kaiser-chris/pdx-parser-go/blob/main/victoria3/buildings.go) and the [Victoria 3 Analysis parser](https://github.com/shabbygaybar/victoria3-analysis/blob/main/src/vic3_analysis/parse/buildings.py). The former explicitly notes the documentation discrepancy. We use those script-facing fields and check them offline. These parsers are independent source implementations, not engine execution evidence.

The new building group explicitly sets `is_government_funded = yes` under native `bg_government`. The university icon, the `empiricism` technology and `law_isolationism` remain native dependencies; `tools/validate.py --game-dir` can check that these names exist in an actual installation. This machine has no detected game installation, so native asset resolution, budget integration, GUI visibility and version-specific loading remain unverified.

The tests execute a strict subset of the shipped country effects, conditions and values with mock building occupancy, reserves, laws and war state. They do not emulate hiring, qualification, the economy, research calculations, GUI bindings or engine scheduling. Archive checks do not certify game compatibility.
